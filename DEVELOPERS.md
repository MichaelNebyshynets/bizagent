# Развёртывание через Docker

В корне выполните `docker compose up -d --build`. После загрузки модели откройте http://localhost:8080. Перед первым входом задайте пароль владельцу:

```sh
docker compose exec backend python -c "import os,runpy,sys; from pathlib import Path; os.environ['DATABASE_URL']='host=postgres dbname=bizagent_db user=postgres password='+Path('/keys/db').read_text(); sys.argv=['set_password.py','owner@uyut.by']; runpy.run_path('set_password.py',run_name='__main__')"
```

Для остановки выполните `docker compose down`. База PostgreSQL 17, документы и модель сохраняются в томах. У прежнего режима разработки свой том PostgreSQL и файл `docker-compose.dev.yml`. При переносе существующей базы между основными версиями PostgreSQL используйте резервную копию и восстановление.
# БизнесПомощник · РБ

Веб-система для малого бизнеса с ИИ-агентом. Бэкенд: `bizagent` (FastAPI). Фронтенд: `biznes-frontend` (React + Vite).
Подробное описание проекта и решений: [PROJECT_CONTEXT.md](PROJECT_CONTEXT.md).

## Запуск одной командой

```bash
python3 run.py         # Windows: py run.py
```

Скрипт сам:
1. создаст `.env` из `.env.example` (настройки базы и модели);
2. поднимет Postgres в Docker, при первом запуске создаст таблицы и зальёт демо-данные;
3. проверит Ollama и модель (и запустит Ollama, если она установлена, но не запущена);
4. поставит недостающие зависимости бэкенда и фронтенда;
5. запустит бэкенд и фронтенд в этом же окне и откроет http://localhost:5173.

Остановить: **Ctrl+C**. Postgres остаётся работать в Docker (`docker compose stop`, чтобы остановить).

В PostgreSQL вход работает по email и паролю. Для каждого существующего
аккаунта один раз задай пароль в терминале, например:

```bash
python3 run.py --set-password owner@uyut.by
python3 run.py
```

Команда запросит пароль без отображения на экране и автоматически подготовит
схему PostgreSQL. Остальные учебные аккаунты можно настроить так же
(`manager@uyut.by`, `accountant@uyut.by`, `owner@flora.by`). Ранее выданные
токены нужно заменить повторным входом. В `--mock` доступны демо-кнопки.

| Нужно | Зачем |
|---|---|
| Python 3.10+ | бэкенд |
| Node.js 18+ | фронтенд |
| Docker Desktop (запущенный) | Postgres с pgvector |
| Ollama + `ollama pull qwen2.5:7b` | локальная модель (можно без неё: `LLM_PROVIDER=mock` в `.env`) |

Варианты:
- `python3 run.py --mock` — без Docker и Postgres, данные в памяти (вход через демо-кнопки);
- `python3 run.py --no-browser` — не открывать браузер.

Модель, базу и таймауты меняйте в `.env` (не в `.env.example`).

## Импорт продаж

Владелец или бухгалтер может загрузить исторические продажи в чате через
«Импортировать продажи». Требуется PostgreSQL. Результат виден в «Аналитике». Пример CSV в UTF-8:

```csv
date,order_id,sku,quantity,price
2026-11-20,SALE-001,SKU-123,2,15.50
```

Используйте существующие артикулы компании и свои номера заказов. Строки
с одним номером образуют один заказ и должны иметь одну дату. После проверки
файла подтвердите сохранение. Уже загруженные номера пропускаются, остатки
склада сохраняются, а себестоимость берётся из каталога на момент импорта.

График включает все продажи компании за выбранный период. В демо-компании
импортированные продажи прибавляются к учебным. При запуске через `run.py`
существующая схема PostgreSQL обновляется автоматически.

Для новой базы без учебных продаж установите `SEED_DEMO_DATA=0` в `.env`
перед первым запуском. Компанию, пользователя и каталог товаров в такой
базе требуется завести отдельно. Параметр применяется при заполнении пустой
базы, ранее загруженные продажи сохраняются.

В чате кнопка «История импортов» показывает сохранённые загрузки компании:
имя файла, время, автора, число заказов и строк, повторы и выручку.
Предпросмотры, неудачные загрузки и файлы без новых заказов в историю
не попадают. История начинается с первого импорта после обновления.

## Реестр заказов

Вкладка «Заказы» показывает продажи компании из PostgreSQL. Фильтры
работают по датам включительно и по точному внутреннему или внешнему
номеру. Нажмите номер, чтобы увидеть позиции, цены и сумму заказа.
Для новых загрузок в истории импорта доступен переход к заказам файла.
Ранее импортированные заказы доступны в общем списке.

## Отмена импорта, закупки и сотрудники

- В чате откройте «История импортов», затем «Отменить импорт». Предпросмотр
  показывает помесячное изменение. После подтверждения связанные заказы
  получают статус отменённых, выручка пересчитывается, а в истории остаются
  дата и автор отмены. Номера отменённых заказов можно импортировать заново.
- Владелец и менеджер могут открыть «Закупки». Черновик можно подготовить
  по остаткам или открыть из рекомендации ассистента в чате. После правок
  проверьте поставщика и позиции и подтвердите сохранение. Запись
  сохраняется в проекте и не отправляется поставщику автоматически.
- Владелец управляет сотрудниками. Для нового аккаунта задайте начальный
  пароль длиной 12–128 символов и передайте его сотруднику напрямую.
  При смене роли и отключении доступа старая сессия перестаёт действовать.
